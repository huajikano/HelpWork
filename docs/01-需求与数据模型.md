# HelpWork 需求与数据模型

> 版本：v1（阶段 1 交付物） · 本文档描述 HelpWork 的数据结构、界面布局与操作路径，作为后续开发的基准。

## 1. 项目定位

HelpWork 是一台 Windows 11 电脑上单人使用的**本地工作流档案柜**：

- 把重复性工作固化成一条条「流程」，每条流程由有序「节点」组成；
- 每个节点挂上做这一步真正要用的「附件」（素材 / 文档 / 脚本 / 模板），文件**真正复制进数据目录**，不存易断的外部路径；
- 打开流程 → 按步骤取用文件，替代"去资源管理器各个角落翻找"。

不做：账号登录、多用户、云同步、联网功能（运行期零网络请求）、流程图画布、Office/PDF 在线预览（一律调系统默认程序打开）。

## 2. 数据目录结构

```
HelpWorkData\                          # 数据目录（默认在 exe 同级，绿色版便携）
  helpwork.db                          # SQLite 主库（单一数据库文件，WAL 模式）
  files\                               # 附件实体仓库
    <sha256 前 2 位>\
      <sha256>_<原始文件名>            # 按内容哈希命名，天然去重
    tmp\                               # 导入中转目录（导入完成后自动清理）
  backups\
    backup_YYYYMMDD_HHmmss.zip         # 自动/手动备份，保留最近 7 份
  logs\
    app.log                            # 运行日志，超 2MB 滚动，保留 3 份
```

- 当前数据目录路径记录在 `%APPDATA%\HelpWork\config.json`，可在设置中更改（支持指向已有数据目录完成跨机迁移）。
- 首次启动：目录不存在则自动创建并建表；表结构升级通过 `meta.schema_version` 迁移。

## 3. 实体与关系

```
workflow 1 ── n node 1 ── n attachment
（删除均软删除 deleted_at；回收站还原；彻底删除时才动实体文件）
```

### 3.1 workflow（流程）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | UUID |
| name | TEXT NOT NULL | 流程名 |
| description | TEXT | 描述（可空） |
| sort_order | INTEGER | 左栏显示顺序，从 0 起 |
| created_at / updated_at | TEXT | ISO 时间 |
| deleted_at | TEXT | 软删除标记，NULL 为正常 |

### 3.2 node（节点）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | UUID |
| workflow_id | TEXT FK→workflow.id | ON DELETE CASCADE |
| title | TEXT NOT NULL | 节点标题 |
| note | TEXT | 备注，支持中文与换行 |
| sort_order | INTEGER | 中栏顺序，从 0 起 |
| created_at / updated_at / deleted_at | TEXT | 同上 |

### 3.3 attachment（附件）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | UUID |
| node_id | TEXT FK→node.id | ON DELETE CASCADE |
| sha256 | TEXT | 内容哈希（去重键） |
| original_name | TEXT | 原始文件名（显示/重命名只改这里，不动实体） |
| stored_path | TEXT | 相对 files\ 的实体路径 |
| size | INTEGER | 字节数 |
| ext | TEXT | 小写扩展名（图标用） |
| created_at / deleted_at | TEXT | 同上 |

### 3.4 meta

`key TEXT PK, value TEXT` —— 记录 `schema_version`、`last_auto_backup_date` 等。

### 3.5 索引与搜索

- 索引：node(workflow_id)、attachment(node_id)、attachment(sha256)、各 deleted_at。
- 搜索范围：node.title / node.note / attachment.original_name（跨流程）。
- 实现：启动时尝试创建 FTS5 虚表与同步触发器（若可用则保留作扩展能力）；**实际查询采用 LIKE '%关键词%'**——中文无空格分词，FTS5 默认 tokenizer 无法命中中文子串，LIKE 对中英文子串效果等价且更符合本工具场景。

### 3.6 删除与清理规则

1. 删除流程 → 该流程及其节点、附件全部软删除（进回收站）；
2. 回收站「还原」→ 按原 sort_order 还原回原位置（若父级也被删则一并还原父级）；
3. 回收站「彻底删除」→ 删行 + 对每个受影响 sha256 做引用计数检查：无其他未删除附件引用该哈希时，才删除 `files\` 下实体文件；
4. 同一文件挂到多个节点只存一份实体（sha256 去重），互相独立显示与命名。

## 4. 三栏界面线框

```
┌────────────────────────────────────────────────────────────────────┐
│ HelpWork 工作流档案柜   [全局搜索…（跨流程检索）]   [回收站] [设置]    │
├──────────────┬───────────────────┬────────────────────────────────┤
│ + 新建流程    │ 当前流程名    [+添加节点] │ 节点标题（点击原地编辑）        │
│ [筛选框]      │                   │ ┌──────────────────────────┐ │
│ ┌──────────┐ │ ┌────┐ ┌────┐     │ │ 备注（多行，自动保存·已保存）│ │
│ │▶流程A (5) │ │ │① 节点│ │② 节点│  ←拖│ └──────────────────────────┘ │
│ │ 流程B (3) │ │ │  📎2│ │  📎1│    │ │ 附件区                        │
│ │ 流程C (0) │ │ └────┘ └────┘     │ │ ┌────────┐┌────────┐      │
│ └──────────┘ │  上下移动/拖拽排序   │ │ │📄a.docx│ │🔤b.py │ 拖入  │
│  ↑拖拽排序    │  右键：重命名/移/删  │ │ └────────┘└────────┘      │
│  右键：重命名/ │                   │ │ [+添加文件]  2 个附件 · 共3.2MB│
│  导出/删除    │                   │ └──────────────────────────┘ │
├──────────────┴───────────────────┴────────────────────────────────┤
│ 📁 D:\…\HelpWorkData（点击打开）        v1.1.0 · 已用 128 MB         │
└────────────────────────────────────────────────────────────────────┘
```

- 左栏：流程列表（名称 + 节点数角标），拖拽排序，右键菜单。
- 中栏：当前流程节点列表（序号 + 标题 + 附件数角标），拖拽/上下移动排序，选中联动右栏；跳转高亮 2 秒。
- 右栏：节点详情 = 标题（原地编辑）+ 备注（防抖 500ms 自动保存，显示"已保存"）+ 附件区 + 底部统计。
- 全局空状态：如"还没有流程，点击左上角「新建流程」开始"。

## 5. 五类核心操作路径

| 操作 | 路径 | 快捷方式 |
|---|---|---|
| 新建流程 | 左栏「+ 新建流程」→ 输入名称 | — |
| 新建节点 | 中栏「+ 添加节点」 | 选中中栏后 `Ctrl+N` |
| 挂文件 | 附件区拖入 / 「+ 添加文件」选择 | `Ctrl+O`（选中节点时） |
| 打开文件 | 双击附件 / 右键「打开」 | `Enter`（附件选中时） |
| 全局搜索 | 顶部搜索框输入即搜 | `Ctrl+F` 聚焦；`Esc` 关闭结果 |

其它：`F2` 重命名（列表选中项）、`Delete` 删除选中（二次确认）、`Ctrl+Shift+Z` 打开回收站、窗格关闭前强制保存备注。

## 6. 边界情况处理

| 场景 | 处理 |
|---|---|
| 单文件 > 500MB | 导入前弹窗"该文件较大，确认要复制进档案柜吗"，确认后走异步进度复制 |
| 拖入文件夹 | 提示"请拖入文件，暂不支持整个文件夹" |
| 重名文件 / 同内容重复挂载 | 同 sha256 只存一份实体，各自显示原名 |
| 数据目录被移走/不可访问 | 启动或切换时检测，中文提示引导重新选择目录，不崩溃 |
| 打开附件失败（无关联程序） | shell 返回非空错误串 → toast 中文提示"系统没有能打开此文件的程序" |
| 超长路径/中文/空格 | 全部 Node path API 处理；文件系统操作统一加 `\\?\` 长路径前缀 |
| 窗口关闭时有未保存备注 | 关窗事件里强制 flush 保存 |
| 二次启动 | 单实例锁，聚焦已有窗口 |
| 导入 zip 损坏/非本工具导出 | 校验 workflow.json 结构，失败给中文提示且不落任何数据 |
| 备份占用 | 自动备份在启动 8 秒后静默执行，WAL checkpoint 后打包，保留 7 份 |

## 7. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | Electron 36 + React 18 + TypeScript + Vite | 任务书推荐；Electron 36 内嵌 Node 22.14 |
| 数据库 | **`node:sqlite`（内置 DatabaseSync）** | 免原生编译（better-sqlite3 需 node-gyp，受网络/工具链制约）；仍落盘单一 helpwork.db；任务书明确许可的备选 |
| 打包 | electron-builder → dir + zip | 免安装绿色版，解压即用 |
| zip | adm-zip（纯 JS） | 导出/导入/备份 |
| 图标 | 内联 SVG | 无 CDN 依赖，完全离线 |

## 8. 阶段划分（对齐任务书）

1. 本文档（不停止等待确认，随阶段推进迭代）；
2. 可运行骨架：三栏布局 + 数据目录初始化 + 建表 + schema 版本 + 空状态；
3. 流程 CRUD 与拖拽排序；
4. 节点 CRUD、备注自动保存；
5. 附件导入（异步复制 + 进度 + 取消 + 哈希去重）、打开/定位/重命名/移除、级联清理；
6. 全局搜索定位高亮、回收站、数据目录设置与迁移；
7. 导出/导入 zip、手动 + 每日自动备份（保留 7 份）；
8. electron-builder 绿色版打包、使用说明、自测表 A1–A8 实测。
