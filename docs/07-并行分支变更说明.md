# 并行分支变更说明

## 勘查报告摘要

- **原存储**：Electron 36 + React/TypeScript；`node:sqlite` 单库 `helpwork.db`（WAL）；`workflow / node / attachment / meta` 关系表。
- **原线性节点**：`src/shared/types.ts` 的 `NodeItem`；`services.ts` 创建、更新、排序、删除、恢复；IPC 在 `src/main/ipc.ts`；中栏在 `src/renderer/src/App.tsx`；导出导入在 `src/main/transfer.ts`。
- **真实旧格式样例**：[`samples/示例：插件发布流程_20261029_145655.zip`](../samples/示例：插件发布流程_20261029_145655.zip) 及解出的 [`samples/旧格式-线性流程_v1.workflow.json`](../samples/旧格式-线性流程_v1.workflow.json)，`workflow.json` 为 v1 线性列表。旧库 v1 样例在 `scripts/selftest.mjs` 中用真实 v1 表定义和记录构造并验证。
- **改动前回归基线**：`npm run build` 成功；服务层 `node scripts/selftest.mjs` 为 32 通过 / 0 失败。改动前 `npm run typecheck` 有一个既存 `Common.tsx` `draggable: boolean` 与 literal `true` 类型不匹配，后续以 `true as const` 修复，因此最终类型检查为全通过。

## 存储冲突点与取舍

1. 原模型只有流程内全局 `sort_order`，没有分叉父子结构。采用 SQLite 适配：加 `branch` 表及 `node.parent_id / branch_id`，不转储或重写旧记录；旧节点自然视为主线。
2. `parent_id` 采用“分支挂接的分叉点”语义；branch 内列表仍按 `sort_order` 排序。此约定复用现有上下移动，并避免把同一分支后续步骤误识别为节点子树。
3. 分叉点可在任意历史步骤创建；门控只禁止相关路径继续追加，不回滚既有历史。服务层强制门控，UI 同步禁用按钮并给出具体分支名。
4. 无分支流程保持 v1 的列表外观和交互；有分支流程采用普通缩进列表，不引入画布依赖。
5. 新旧导入结构不同：v1 包以单主线导入；v2 包由节点/分支映射表重建 ID 引用。未知 JSON 属性保存到 `extra_json`，输出时保留。
6. 对完成状态的假设：外层分支不能在存在未完成嵌套分支时标为完成；已完成分支只读结构性操作（不能追加/再分叉），已有记录可继续编辑。

- `npm run build`：主进程 `tsc` 与 Vite renderer 均通过。
- `npm run selftest`：87 通过 / 0 失败（32 个原线性用例 + 新增分支、v1 迁移/v1-v2 包往返、重开恢复、未知字段透传等断言）。

## 回滚方式

退出程序，将 v2 数据目录 `helpwork.db` 备份另存；从 `backups/pre_migration_v1_to_v2_时间戳.db` 恢复旧库文件并使用 schema v1 兼容程序。迁移只触碰数据库结构，不改附件实体路径。若 v2 已记录分支内容，应先用 v2 导出包留档，因为 v1 程序不支持分支数据。
