# 并行分支已知限制与本期取舍

## 本期明确不支持

1. **条件分支**：不按数据/条件决定走哪条支路，所有并行分支都运行。
2. **部分汇合**：分叉点必须等待所有直接分支显式完成；不支持“完成任意 K 条即可继续”。
3. **DAG 合并**：一个节点只有一个 `branch_id` 和一个分叉挂点；分支之间不能合流到同一个节点，也不支持跨流程引用。
4. **流程图画布/拖拽改父子关系**：使用缩进树形列表。已有上下移动/主线拖拽仅在同一列表顺序中调整，不允许拖节点跨分支改父关系。
5. **分支节点级别的跨分支移动 UI**：不提供“把某一步搬到另一个分支”的菜单。服务层提供受校验的整分支移动函数供结构维护；其目标若在自身子树内或跨流程会拒绝。

## 语义边界和假设

- **parentId 定义**：`parent_id` 是“分支挂到哪个分叉点”，不是本分支中前一步的链表指针；branch 内的步骤由 `branch_id + sort_order` 组成独立线性序列。这样排序不会因步骤重排造成循环，节点删除也不会把同分支后续步骤误认为子节点。
- **任意已有节点均可分叉**：允许在既有主线/分支步骤上增加分支。创建后，未完成分叉点之后的路径追加会受门控；已有历史步骤不被自动删除或重排。
- **完成状态覆盖**：外层分支只有在所有层级内的嵌套分支完成后才能标记完成。完成后不能新增步骤/嵌套分支，但允许编辑已有标题、备注、附件；取消完成后恢复追加。
- **空分支**：若用户删除分支中的唯一步骤，该分支记录仍保留、状态仍为进行中，主线仍被门控；可在该分支添加新步骤、显式标记完成或删除分支。
- **删除规则**：删除分叉点有活动分支时服务端拒绝，必须先处理分支；删除分支前 UI 必须确认，并递归软删除其嵌套结构。回收站用分支整体条目表达，不提供将分支自动合并回主线的行为。
- **完成后撤销**：取消完成会重新启用相应门控。如果用户此前在该分叉点之后已有主线历史步骤（例如后来在任意历史节点新增分支），已有历史不回滚，但新的追加会被阻止。
- **层级展开**：可无限嵌套（受实际数据量与界面高度约束），展开状态未独立持久化；重启时恢复最后选择位置并自动展开当前路径。
- **未知扩展字段**：导入 JSON 中流程/节点/分支/附件的未知属性保存在 `extra_json` 并在导出时透传；数据库中已有未知列不做 DROP。JSON 若无法解析则按导入失败处理，不静默丢弃源包。
- **旧库备份**：升级备份是 SQLite `.db` 快照，不包含附件实体目录（迁移只改 schema、不动实体文件）。建议同时保留现有每日/手动全量 zip 备份。

## 后续可选项（非本期）

- 面向大量分支的树视图虚拟滚动、快速搜索分支名和折叠状态保存。
- 分支整体移动的可视化目标选择器；逐节点跨分支移动前需定义附件与嵌套分叉迁移规则。
- 可配置的完成策略/汇合策略；这会改变本期“显式完成 + 全部等待”的已确认语义，不应作为默认行为悄悄加入。
