# HelpWork 并行分支数据结构说明

## 持久化方式与版本

HelpWork 使用 SQLite 单文件 `helpwork.db`，当前 `meta.schema_version = 2`。v2 在原 `workflow / node / attachment / meta` 上增加并行结构字段与 `branch` 表；不迁移、不重写旧节点内容。

| 实体 | 字段 | 类型 | 说明 |
|---|---|---|---|
| workflow | `id` | TEXT PK | 流程 id |
|  | `name`, `description`, `sort_order`, `created_at`, `updated_at`, `deleted_at` | 原字段 | v1 原样保留 |
|  | `extra_json` | TEXT NULL | 未识别 JSON 字段透传袋 |
| node | `id`, `workflow_id`, `title`, `note`, `sort_order`, 时间字段 | 原字段 | 节点/工作记录，旧字段不丢 |
|  | `parent_id` | TEXT NULL | 主线为 NULL；分支内节点指向该分支的分叉点节点（嵌套分支节点可属于外层分支） |
|  | `branch_id` | TEXT NULL | 主线为 NULL；分支步骤指向所属 `branch.id` |
|  | `extra_json` | TEXT NULL | 导入包中未识别节点字段的 JSON 扩展袋 |
| branch | `id` | TEXT PK | 分支 id |
|  | `workflow_id` | TEXT FK→workflow.id | 所属流程 |
|  | `fork_node_id` | TEXT FK→node.id | 分叉点节点 |
|  | `name` | TEXT NOT NULL | 用户可编辑分支名 |
|  | `status` | TEXT | `active` / `done`，显式完成状态 |
|  | `completed_at` | TEXT NULL | 最近一次标记完成时间；取消完成时清空 |
|  | `sort_order` | INTEGER | 同分叉点下的分支顺序 |
|  | 时间字段、`deleted_at` | TEXT | 创建/更新/软删除信息 |
|  | `extra_json` | TEXT NULL | 未识别分支字段透传袋 |
| attachment | 原字段 + `extra_json` | TEXT NULL | 附件实体沿用节点外键和哈希机制；未知 JSON 字段可以透传 |

### 排序和关系约定

- 主线：`branch_id IS NULL AND parent_id IS NULL`，按 `sort_order, created_at` 排序。
- 分支：`branch_id = 某 branch.id`，其节点按分支内 `sort_order, created_at` 排序；分支内所有节点的 `parent_id` 指向 branch 的 `fork_node_id`。节点“属于哪条路径”由 `branch_id` 确定，`parent_id` 标识挂接点。
- 分支根节点是创建分支时自动生成的首个步骤。后续步骤与根节点同属 branch，由分支内 `sort_order` 排列。
- 嵌套分支：内层 branch 的 `fork_node_id` 可以指向外层 branch 的某个节点；内层节点自己的 `branch_id` 指向内层 branch。节点仍只有一个分支归属，不允许 DAG 多父引用。
- 同一分叉点的 N 条分支必须 N≥2。完成状态由用户显式切换，不以“最后一步录入”自动推断。

## v2 导出 JSON 样例

完整、可直接导入的新格式样例见 [`samples/新格式-两层嵌套并行分支_v2.workflow.json`](../samples/新格式-两层嵌套并行分支_v2.workflow.json) 和配套 zip。其结构缩写如下（id 为示意）：

```json
{
  "format": "helpwork-workflow",
  "version": 2,
  "workflow": { "id": "wf-1", "name": "插件发布", "description": null },
  "nodes": [
    { "id": "main-1", "title": "拆分任务", "parent_id": null, "branch_id": null, "sort_order": 1, "note": null, "attachments": [] },
    { "id": "ui-1", "title": "界面 · 开始", "parent_id": "main-1", "branch_id": "b-ui", "sort_order": 0, "note": null, "attachments": [] },
    { "id": "style-1", "title": "样式 · 开始", "parent_id": "ui-1", "branch_id": "b-style", "sort_order": 0, "note": null, "attachments": [] }
  ],
  "branches": [
    { "id": "b-ui", "fork_node_id": "main-1", "name": "界面", "status": "done", "completed_at": "…", "sort_order": 0 },
    { "id": "b-style", "fork_node_id": "ui-1", "name": "样式", "status": "done", "completed_at": "…", "sort_order": 0 }
  ]
}
```

额外未知 JSON 属性在导入时保存进对应行的 `extra_json`，再次导出时与已知字段合并透传；顶层未知属性也暂存在 workflow 的扩展袋中。已知字段以数据库当前值为准。坏格式/引用缺失的 v2 包会在导入时给中文错误并回滚新建流程。

## v1 兼容映射

- v1 没有 `branches`、`parent_id`、`branch_id`：导入时按旧 `nodes` 顺序创建主线节点，两个 v2 字段均为 NULL。
- v1 SQLite 旧库迁移仅新增空分支字段/表及扩展 JSON 列；旧节点 id、标题、备注、顺序、时间、删除标记和附件引用保持不变。
- `extra_json` 不替代或重命名任何 v1 字段。未知 JSON 字段原样透传；未识别的数据库原列不会被 DROP 或重建。

## 迁移前备份和回滚

- 打开数据库时，在任何建表/ALTER 写入前检测缺少 v2 结构的非空旧库；先 `wal_checkpoint(TRUNCATE)`，再将原 `helpwork.db` 复制到 `HelpWorkData/backups/pre_migration_v1_to_v2_YYYYMMDD_HHmmss.db`（若 schema 版本缺失，以 v1 命名）。
- 备份失败时升级中止并显示中文错误，不带着未备份库继续写入。
- 回滚：退出 HelpWork；将当前 `helpwork.db` 与 `-wal/-shm` 一并移出数据目录；把迁移前的 `.db` 备份复制回 `helpwork.db`；使用兼容 schema v1 的旧版程序启动。分支功能产生的数据不在 v1 中，回滚到 v1 前应先从 v2 导出分支流程留档。

## 完成门控规则

对主线末尾以及分支末尾追加步骤时，若相应路径上存在未完成分叉，则拒绝追加并返回未完成分支名称；前端显示提示并禁用追加按钮。外层分支存在未完成嵌套分支时，拒绝继续追加，也不允许将外层标记完成。此规则在服务层再次校验，不能仅靠 UI 绕开。
